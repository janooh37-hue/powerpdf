PowerPDF desktop installation

These installers contain the real windowed PowerPDF GUI and a separate frozen
powerpdf TUI/command-line executable. No Python, uv, Ghostscript or Tesseract
installation is required. Keep each application bundle intact; copying out an
executable alone loses its libraries, assets and helper runtimes.

Verify the download against the release SHA256SUMS and repository provenance
before bypassing any unsigned-publisher warning.

Windows x64
Download powerpdf-<version>-windows-x64-setup.exe and run it. The default install
is per-user under %LOCALAPPDATA%\Programs\PowerPDF; all-users installation is
optional. Launch PowerPDF from the Start Menu for the GUI. The installer adds
its bin directory to PATH: open a NEW terminal, then use:
  powerpdf
  pdfsplit --help
  pdfmerge --help
  pdfcompress --help
  pdfimage --help
  pdfprint --help
powerpdf opens the TUI; the other commands are command-line adapters. pdfprint
is Windows-only and retains the bundled PowerShell/fzf printing workflow.
Unsigned setup may trigger SmartScreen: for a verified download, choose More
info / Run anyway. Uninstall through Windows Settings / Apps.

The powerpdf-<version>-windows-x64.zip portable edition contains the same
runtime but does not change PATH or create shortcuts. Extract the entire archive,
launch bin\powerpdf-gui.exe, and invoke commands from its bin directory or add
that directory to your user PATH yourself.

macOS 13+ (Apple Silicon or Intel)
Choose powerpdf-<version>-macos-arm64.dmg for Apple Silicon or
powerpdf-<version>-macos-x64.dmg for Intel. Mount it and drag PowerPDF.app to
Applications. The app is ad-hoc signed, not Developer ID signed or notarized.
For a verified download, try Finder right-click / Open. If quarantine still
blocks it, remove quarantine from this application ONLY:
  xattr -dr com.apple.quarantine /Applications/PowerPDF.app
Do not disable Gatekeeper globally. Homebrew is not required.

Double-click PowerPDF.app for the GUI. Terminal commands live in
/Applications/PowerPDF.app/Contents/MacOS. For convenient user-local commands:
  mkdir -p "$HOME/.local/bin"
  for command in powerpdf pdfsplit pdfmerge pdfcompress pdfimage; do
    ln -sf "/Applications/PowerPDF.app/Contents/MacOS/$command" "$HOME/.local/bin/$command"
  done
Add $HOME/.local/bin to your shell PATH, then run powerpdf for the TUI or, for
example, pdfsplit --help. Keep the app installed at the symlink target. Remove
the app and these symlinks to uninstall.

Linux x64
The native build baseline is Ubuntu 22.04. For the Debian package:
  sudo apt install ./powerpdf-<version>-linux-x64.deb
Launch PowerPDF from the desktop menu. The package installs under /opt/powerpdf
and supplies /usr/bin/powerpdf, /usr/bin/pdfsplit, /usr/bin/pdfmerge,
/usr/bin/pdfcompress and /usr/bin/pdfimage. Run powerpdf for the TUI or invoke
an adapter with --help. Remove with sudo apt remove powerpdf. PDF Open With
registration does not silently change your default PDF application.

For the portable AppImage:
  chmod +x powerpdf-<version>-linux-x64.AppImage
  ./powerpdf-<version>-linux-x64.AppImage
The default is the GUI. Use --cli for the console entry point:
  ./powerpdf-<version>-linux-x64.AppImage --cli
  ./powerpdf-<version>-linux-x64.AppImage --cli split --help
The other subcommands are merge, compress and image. If FUSE is unavailable:
  ./powerpdf-<version>-linux-x64.AppImage --appimage-extract
  ./squashfs-root/AppRun
  ./squashfs-root/AppRun --cli split --help
Keep the extracted squashfs-root intact. AppImage installation needs no root;
delete the AppImage or extracted directory to remove it.

Bundled runtimes and licensing
Ghostscript 10.08.0, Tesseract 5.5.0 and Leptonica 1.85.0 ship with the native
helper closure, OCR models, fonts and license notices. Application LICENSE and
NOTICE are included in the frozen runtime. PowerPDF is AGPL-3.0-or-later.
Release assets include ghostscript-10.08.0-source.tar.xz and
powerpdf-corresponding-source.tar.gz; see bundled third-party notices for the
remaining licenses and source pointers.

Desktop display servers, printer drivers/spoolers and GPU kernel drivers remain
OS facilities. CI artifact smoke tests use an offscreen display and do not
qualify physical printer output or every desktop environment.

Native CI diagnostics
After packaging, CI runs:
  uv run --frozen python packaging/smoke/install-artifacts.py
The installed real MainWindow is captured in
build/evidence/**/powerpdf-gui.png alongside runtime/linkage and CLI/OCR evidence.
The stdlib-only external probe can also be invoked with:
  python packaging/smoke/product-smoke.py --gui PATH --cli PATH --output DIR
The launcher's private --packaging-smoke-output DIR diagnostic captures the real
rendered application and exits after orderly worker shutdown; it is not a
separate smoke application. All fixture construction and transformation checks
remain outside the frozen product. The clean Ubuntu 24.04 AppImage gate runs
without network access and never installs missing dependencies into the container.
